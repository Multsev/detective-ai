# Публикация и выпуск версий

## Первый push

1. Создайте на GitHub пустой репозиторий без README, `.gitignore` и лицензии.
2. Проверьте локальную историю: `npm run security:secrets -- --history`.
3. Добавьте удалённый адрес: `git remote add origin <SSH-или-HTTPS-адрес>`.
4. Отправьте ветку: `git push -u origin main`.
5. Убедитесь, что workflow **CI** завершился успешно.
6. Откройте GitHub и вручную проверьте дерево: `data/`, `.env` и пользовательских экспортов быть не должно.

## Обычная работа

- Каждая задача выполняется в отдельной ветке и попадает в `main` через Pull Request.
- CI обязан пройти до слияния.
- Новые изменения сначала записываются в раздел `Unreleased` файла `CHANGELOG.md`.

## Новый релиз

```bash
git switch main
git pull --ff-only
npm ci
npm run verify
npm run security:secrets -- --history
npm version patch   # minor или major по смыслу изменения
git push origin main --follow-tags
```

После push создайте GitHub Release из нового тега `vX.Y.Z` и перенесите в описание соответствующий раздел `CHANGELOG.md`. Не прикладывайте каталог `data`, `.env`, локальные логи и экспортированные дела.

## Удаление локальной рабочей копии

Удалять рабочую копию можно только после того, как:

1. `git status` пуст;
2. commit и тег видны на GitHub;
3. CI завершился успешно;
4. свежий clone в другую временную папку проходит `npm ci && npm run verify`;
5. нужные пользовательские дела и материалы отдельно зашифрованы или сознательно удалены.

Сам GitHub не является резервной копией пользовательского каталога `data/`, потому что этот каталог намеренно не публикуется.
